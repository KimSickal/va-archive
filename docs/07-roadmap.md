# 07. 구현 순서와 향후 확장

## 1. 사전 준비 (사용자)

- 이 디렉토리를 git 레포로 만들고 GitHub 원격 레포를 생성한다.
- GitHub Pages 소스를 **GitHub Actions**로 설정한다.
- 로컬에 `gh` CLI를 설치하고 인증한다(PR 생성·머지용).
- 수집 흐름이 바로 머지하는 구조이므로, `main` 브랜치 보호 규칙에서 `validate` 체크만 필수로 지정할 것을 권장한다(리뷰 승인은 필수로 하지 않음).

## 2. 마일스톤

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| **M1. 데이터 기반** | 스키마 4종, `validate-data`, 데이터 타입, 수작업 샘플 데이터(작품 2~3개, 교체와 겸역 사례 포함) | 샘플이 검증을 통과하고, 일부러 넣은 오류를 모두 잡아냄 |
| **M2. 빌드** | `build-data`(인덱스, 검색 키, 마지막 공개일), 단위 테스트 | 교집합, 역인덱스, 재조사 판정 테스트 통과 |
| **M3. 프론트 핵심** | 라우팅, DB 로더, 검색·자동완성, 성우·작품 상세, 재조사 배너 | 샘플 데이터로 F1, F2, F8 동작 |
| **M4. 비교와 즐겨찾기** | 작품/성우 비교, 즐겨찾기 저장소, 내보내기·가져오기, 즐겨찾기 강조, 즐겨찾기 프랜차이즈와 비교, 스포일러 가림 | F3~F7, F9 동작, Playwright 스모크 테스트 통과 |
| **M5. 배포** | `validate.yml`, `deploy.yml`, Pages 배포 | main에 푸시하면 github.io에 반영됨 |
| **M6. 수집 파이프라인** | `.claude/` 스킬(add-work·research·verify·resolve-conflict), `person-id`·`lock`·`skill-hash`(구현됨), `stale-report`, `CLAUDE.md` | 실제 작품 1개를 `/add-work`로 처음부터 끝까지 처리해 PR 머지까지 완료 |
| **M7. 데이터 확충** | 작품을 늘려 가며 스킬 지침 보정 | 애니 20개 + 게임 5개 |

M1~M2와 M6의 스킬 초안은 병렬로 진행할 수 있다(스키마만 확정되면 됨).

## 3. 남은 데이터 작업 (보류)

- **첫 등장 화수** (`Character.first_appearance.episode`): 첫 등장 작품은 모두 기록되어 있으나, TV 작품 캐릭터 295명(주연·조연 136명)의 화수가 비어 있다 (2026-11-13 기준: 헌터×헌터 193, 강철의 연금술사 68, 건담 00 34). 캐릭터마다 회차 조사가 필요한 대규모 웹 작업이므로 보류. 하게 되면 주연·조연부터.
- 캐릭터 후리가나 7건: 출처를 찾지 못함 (お父様, 赤ハロ, 青ハロ, 女王, オロソ兄·妹 등)
- 주연·조연 캐릭터 이미지 77건 없음 (공식 이미지 미확인)

## 4. 향후 확장 후보

- **다국어 UI**: `i18n/en.ts`, `ja.ts` 추가. 데이터는 이미 ja/ko/en을 갖추고 있음. 그 밖의 표시 언어는 [03](03-data-model.md) 2.5절 절차를 따름
- **초성 검색**: 빌드할 때 초성 키만 추가하면 됨
- **새 작품 유형**: 외화·드라마 더빙, 드라마 CD → `type` enum 추가(minor 스키마 변경)
- **사전 렌더링**: 검색 엔진 노출이 필요해지면 빌드 시 작품·성우별 정적 HTML을 생성(경로 기반 라우팅으로 전환)
- **DB 분할 로딩 / SQLite**: [04](04-data-build.md) 1절의 재검토 기준에 도달했을 때
- **통계 페이지**: 성우별 출연 수, 자주 함께 출연하는 성우 쌍 등. 인덱스만으로 계산할 수 있음

# 05. 프론트엔드 명세

## 1. 라우트 (해시 라우팅)

| 경로 | 화면 |
|---|---|
| `#/` | 홈: 통합 검색창, 최근 추가 작품, 즐겨찾기 바로가기 |
| `#/search?q=` | 검색 결과 (성우 / 작품 / 캐릭터 그룹) |
| `#/person/:slug` | 성우 상세. 표시 ID(slug)를 쓰고, 내부 ID·이전 slug·이전 id 도 받아서 현재 slug로 찾아간다 |
| `#/work/:id` | 작품 상세 |
| `#/work/:id/vs-favorites` | 즐겨찾기 프랜차이즈와 비교 결과 |
| `#/compare/works?a=&b=` | 작품 2개 비교 |
| `#/compare/persons?a=&b=` | 성우 2명 비교 |
| `#/franchise/:id` | 프랜차이즈 (작품 목록, 캐릭터 목록) |
| `#/franchise/:id/character/:cid` | 캐릭터 상세 (이미지, 설명, 작품별·버전별 성우) |
| `#/favorites` | 즐겨찾기 관리, 내보내기/가져오기 |
| `#/about` | 출처 정책, 검증 상태 설명, 데이터 빌드 정보 |

`data/redirects.json`에 이전 ID가 있으면 새 ID 경로로 자동 이동한다.

## 2. 공통 컴포넌트

- **GlobalSearch**: 헤더에 항상 노출. 입력할 때마다 자동완성 드롭다운을 띄운다(성우·작품·캐릭터 그룹, 키보드 탐색). Enter를 누르면 `#/search`로 이동한다.
- **EntityPicker**: 비교 화면에서 작품이나 성우를 고르는 자동완성 입력. GlobalSearch와 같은 검색 함수를 쓰되 종류를 하나로 제한한다.
- **FavoriteToggle**: ☆/★ 토글. 프랜차이즈와 성우에 쓴다. 작품 페이지의 토글은 그 작품이 속한 **프랜차이즈**를 즐겨찾기한다(라벨: "「○○」 시리즈 즐겨찾기").
- **SpoilerMask**: 9절 참고.
- **ExternalImage**: 외부 URL 이미지를 지연 로딩(`loading="lazy"`, `referrerpolicy="no-referrer"`)으로 보여주고, 아래에 `credit`과 `page_url` 링크를 붙인다. 로드에 실패하면 이니셜 플레이스홀더로 대체한다.
- **LocalizedText**: `Text` 타입을 표시한다. 표시 언어가 `translated`에 들어 있으면 "번역" 표시와 [원문 보기] 토글을 붙인다.
- **VerificationBadge**: `unverified`(회색 "미검증"), `disputed`(주황 "확인 필요"), `user_confirmed`(파랑 "사용자 확인"). `verified`는 배지를 표시하지 않는다.
- **StalenessBanner**: [04](04-data-build.md) 5절의 규칙을 따른다.
- **SourceList**: 페이지 하단에 출처 목록(등급 표시)과 조사일을 보여준다.
- **LangSection**: 언어별 섹션 헤더. 언어 정렬 순서는 `ja` → `ko` → `en` → 기타 (ISO 코드 알파벳순)로 고정한다.

## 3. 성우 상세 `#/person/:id`

1. **프로필**: 이미지(있을 때), 이름(표시 언어 / 원어 / 로마자), 성별(있을 때), 국적, 출생(정밀도대로 표시), 소속사, 링크, 즐겨찾기 토글
2. **출연작 목록**: `idx.creditsByPerson` 기반
   - 작품 단위로 그룹화하고, 작품 시작일 내림차순으로 정렬한다.
   - 행: 작품명(유형·연도) / 버전 라벨 / 캐릭터명 / 역할 / 비고(`part`, `episodes`, `note`)
   - 한 작품에서 여러 캐릭터를 맡았으면 같은 작품 그룹 안에 여러 행으로 표시한다.
   - **즐겨찾기 강조**: 즐겨찾기한 프랜차이즈에 속한 작품의 행 배경을 강조색으로 칠하고 ★ 아이콘을 붙인다. 목록 상단에 "즐겨찾기 시리즈 N개 출연" 요약과 **[즐겨찾기만 보기]** 필터를 둔다.
   - 필터: 유형(애니/게임), 언어, 역할(주연만 등)
3. "다른 성우와 비교" 버튼을 누르면 `#/compare/persons?a=<id>`로 이동한다(b는 선택 대기 상태).

## 4. 작품 상세 `#/work/:id`

1. **StalenessBanner** (조건부)
2. **기본 정보**: 제목(표시 언어 / 원어 / 로마자), 유형, 상태, 방영/출시 기간, 화수 또는 상영시간, 제작사/개발사/퍼블리셔, 플랫폼, 프랜차이즈 링크(같은 프랜차이즈의 다른 작품 목록), 즐겨찾기 토글
3. **버튼**: [내가 좋아하는 작품과 비교] [다른 작품과 비교]
4. **캐스팅 표**: 행은 캐릭터, 열은 버전(일본어 원판 | 한국어 더빙(○○판) | …)
   - 셀 안에는 성우 링크를 보여준다. 성우가 여럿이면 세로로 나열하고 `part`/`episodes`를 작게 덧붙인다 (예: "A (1–24화) → B (25화~)").
   - 행 순서: role (`main` → `supporting` → `minor`), 같은 role 안에서는 원본 Credit 순서
   - 캐릭터 이름을 누르면 캐릭터 상세로 이동한다.
   - 모바일에서는 표 대신 캐릭터별 카드로 바꾸고, 카드 안에 버전별 성우를 나열한다.
   - 버전 열 표시/숨김 토글
   - **[단역 포함]** 토글: 기본 OFF로 주연·조연만 보여주고, 켜면 단역과 이름 없는 배역까지 표시한다. 꺼져 있으면 숨긴 행 수를 "단역 N명 더 보기"로 안내한다.
   - **[캐릭터 이미지 표시]** 토글: 기본 OFF. 켜면 캐릭터 이름 옆에 썸네일을 표시한다. 설정은 `va-archive:settings`에 저장한다.
5. **SourceList**, 조사일, 검증 상태

## 4-1. 캐릭터 상세 `#/franchise/:id/character/:cid`

- 이미지(항상 표시, 스포일러 캐릭터는 가림), 이름(표시 언어 / 원어 / 로마자), 설명
- 첫 등장 작품·화, 언어별 첫 음성 출연 작품·화. 첫 등장과 첫 음성이 같으면 한 줄로 합친다
- 출연 작품별 표: 작품 / 버전 / 성우 / 비고. 교체 이력이 있으면 회차 순으로 보여준다.

## 5. 작품 비교 `#/compare/works?a=&b=`

- 상단에 EntityPicker 2개와 [바꾸기] 버튼
- 결과는 **언어별 섹션**으로 나눠 `ja` → `ko` → …… 순으로 보여준다. 겹치는 성우가 없는 언어는 "겹치는 성우 없음"으로 접어 둔다.
- 섹션 안의 행: 성우 / 작품 A에서 맡은 캐릭터(들) / 작품 B에서 맡은 캐릭터(들)
- 계산: `intersect(idx.personsByWorkLang[a][lang], idx.personsByWorkLang[b][lang])`
  - 같은 언어끼리만 비교한다. 예를 들어 A의 일본어 원판 성우와 B의 한국어 더빙 성우는 비교하지 않는다.
  - 같은 언어에 더빙판이 여러 개면 합쳐서 비교하고, 캐릭터 옆에 버전 라벨을 붙인다.

## 6. 성우 비교 `#/compare/persons?a=&b=`

- 계산: `intersect(idx.worksByPerson[a], idx.worksByPerson[b])`
- 행: 작품 / A의 배역(버전 라벨 포함) / B의 배역
- 즐겨찾기한 프랜차이즈의 작품은 강조한다.
- 같은 작품이라도 A는 일본어판, B는 한국어판처럼 서로 다른 버전에 출연했다면 "공동 출연"으로 볼지 판단이 필요하다. 기본값은 **같은 버전(동일 음성 트랙)에 함께 출연한 경우만** 공동 출연으로 보고, 토글로 "다른 버전 포함"을 켤 수 있게 한다.

## 7. 즐겨찾기 프랜차이즈와 비교 `#/work/:id/vs-favorites`

- 대상: 즐겨찾기한 프랜차이즈 중 **현재 작품이 속한 프랜차이즈를 제외한** 전부. 즐겨찾기 단위가 프랜차이즈이므로 같은 시리즈끼리 겹치는 문제는 따로 옵션을 두지 않아도 해결된다.
- 비교: 현재 작품의 언어별 성우 집합과, 즐겨찾기 프랜차이즈에 속한 **모든 작품**의 언어별 성우 합집합을 교집합한다.
- 출력 구조 (요구사항대로 언어별로 먼저 나눔):
  ```
  ▼ 일본어
     ★ 「시리즈 X」 — 겹치는 성우 3명
         성우 P : (현재 작품) 캐릭터1  ↔  (X 2기) 캐릭터9, (X 극장판) 캐릭터9
         …
     ★ 「시리즈 Y」 — 겹치는 성우 1명
  ▼ 한국어
     ★ 「시리즈 X」 — 겹치는 성우 2명
     …
  ```
- 상대편 배역은 "작품명 + 캐릭터"로 보여준다. 같은 캐릭터를 여러 작품에서 맡았으면 하나로 합치고 작품명을 나열한다.
- 언어 섹션 안에서는 겹치는 성우 수가 많은 프랜차이즈부터, 수가 같으면 최신 작품 시작일 내림차순으로 정렬한다.
- 즐겨찾기가 비어 있으면 안내 문구와 함께 즐겨찾기 방법을 보여준다.
- 빌드 단계에서 `idx.personsByFranchiseLang`(프랜차이즈 → 언어 → 성우)을 미리 만들어 두므로 즉시 계산된다.

## 8. 즐겨찾기 저장소

### 저장 형식 (`localStorage` 키: `va-archive:favorites`)
```json
{
  "version": 1,
  "updatedAt": "2026-11-12T13:00:00Z",
  "franchises": [{ "id": "frieren", "addedAt": "2026-11-12T13:00:00Z" }],
  "persons": [{ "id": "atsumi-tanezaki", "addedAt": "2026-11-12T13:00:00Z" }]
}
```

### 동작
- 모든 읽기와 쓰기를 `try/catch`로 감싼다. 시크릿 모드나 저장소가 차단된 환경에서는 메모리로 대체하고 "즐겨찾기가 저장되지 않습니다" 안내를 띄운다.
- 다른 탭에서 바뀐 내용은 `storage` 이벤트로 동기화한다.
- 성우 즐겨찾기는 **내부 ID**로 저장한다(표시 ID는 바뀔 수 있음). 내부 ID 도입 전에 저장된 값(예전 ID = 현재 slug)도 slug 조회로 찾는다.
- 현재 DB에 없는 ID(삭제되었거나 ID가 바뀐 항목)는 `redirects.json`으로 매핑해 보고, 그래도 없으면 목록에 "데이터에서 찾을 수 없음"으로 표시한다. 자동으로 삭제하지는 않는다.
- **내보내기**: 위 JSON을 `va-archive-favorites-YYYYMMDD.json` 파일로 다운로드한다.
- **가져오기**: 파일을 선택한 뒤 `version`과 형식을 검증하고 [병합] / [덮어쓰기]를 선택하게 한다. 형식이 올바르지 않으면 거부하고 사유를 표시한다.
- `version`이 올라가면 로드할 때 마이그레이션 함수를 적용한다.

## 9. 스포일러 표시

| 지정 | 기본 표시 | 그대로 보이는 것 |
|---|---|---|
| `character.spoiler` | 캐릭터 이름, 설명, 이미지 자리에 흐림 처리한 **"스포일러"** | 성우 이름과 링크 |
| `credit.spoiler` | 그 배역의 성우 자리에 흐림 처리한 **"스포일러"** | 캐릭터 (캐릭터도 스포일러가 아니라면) |

- 적용 범위: 작품 캐스팅 표, 캐릭터 상세, 성우 출연작 목록, 비교 결과, 프랜차이즈 캐릭터 목록
- **표시하기**: 가려진 항목을 클릭하거나 Enter를 누르면 그 항목만 펼친다. 펼친 상태는 해당 페이지에서만 유지한다(새로고침하면 다시 가려짐).
- **전역 설정**: 설정 메뉴의 "스포일러 항상 표시" 토글. `va-archive:settings`에 저장한다.
- **검색**: 스포일러 캐릭터의 이름은 자동완성 후보에서 제외한다. 다만 사용자가 이름을 정확히 입력하면 이미 아는 것으로 보고, 가린 상태로 결과에 표시한다(클릭하면 펼침). `credit.spoiler` 배역은 성우 검색 결과의 출연작 요약에 나타나지 않게 한다.
- **URL과 제목**: 스포일러 캐릭터 상세 페이지의 `<title>`에는 "스포일러"를 쓴다. 캐릭터 ID도 정체가 드러나지 않는 이름으로 짓는다(수집 지침에 명시).

## 10. 기타

- **i18n**: 모든 UI 문자열은 `src/i18n/ko.ts`의 키로 참조한다. 데이터 표시 언어 선택 규칙은 [03](03-data-model.md) 2.4절을 따른다. 데이터가 이미 ja/ko/en 3개 언어로 저장되므로, UI 문자열만 번역하면 영어·일본어 UI로 확장할 수 있다.
- **테마**: 시스템 다크 모드를 따르고, 수동 토글도 제공한다.
- **반응형**: 360px 폭까지 대응한다. 표는 카드로 바꾼다.
- **접근성**: 키보드만으로 검색·선택·토글이 가능해야 하고, 강조를 색에만 의존하지 않는다(★ 아이콘 병행).
- **SEO**: 해시 라우팅이라 개별 페이지 색인은 포기한다. 필요해지면 빌드 시 정적 페이지를 미리 렌더링하는 방안을 검토한다([07](07-roadmap.md) 참고).

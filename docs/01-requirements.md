# 01. 요구사항과 결정사항

## 1. 기능 요구사항

| ID | 기능 | 설명 |
|---|---|---|
| F1 | 성우 조회 | 이름(원어/로마자/한국어/별칭) 검색 → 공개 프로필(성별, 국적, 출생연도 등) + 사이트에 저장된 출연작과 배역 목록 |
| F2 | 작품 조회 | 작품명 검색 → 기본 정보(방영/출시일, 제작사, 화수 등), 캐릭터 목록, 캐릭터별 언어·더빙판별 성우 |
| F3 | 작품 2개 비교 | 두 작품에 공통으로 출연한 성우를 **언어별로 구분**해 출력 |
| F4 | 성우 2명 비교 | 두 성우가 함께 출연한 작품과 각자의 배역 |
| F5 | 즐겨찾기 | **프랜차이즈**·성우를 즐겨찾기. 브라우저 `localStorage` 저장, JSON 내보내기/가져오기 |
| F6 | 즐겨찾기 강조 | 성우 페이지의 출연작 중 즐겨찾기한 프랜차이즈에 속한 작품을 강조 표시 |
| F7 | 즐겨찾기 작품과 비교 | 작품 페이지의 버튼 → 즐겨찾기한 프랜차이즈 중 성우가 겹치는 프랜차이즈(와 작품)·성우를 **언어별로**(일본어 → 한국어 → …) 출력 |
| F8 | 재조사 안내 | 마지막 방영/출시일보다 자료 조사일이 이전이면 페이지 상단에 "정보가 불완전할 수 있음" 안내 문구 노출 |
| F9 | 스포일러 가림 | 스포일러로 지정된 캐릭터는 이름 등을 기본으로 가리고, 클릭해야 표시 |

## 2. 비기능 요구사항

- 정적 사이트. 런타임에 서버 연산 없음. 100% 브라우저 자원 사용.
- 연산에 필요한 모든 데이터는 레포에 포함.
- 데이터는 자유 서술이 아닌, **스키마로 필드가 엄격히 정의된 구조화 파일**로 저장.
- UI는 한국어 우선. 추후 다국어 확장이 가능하도록 문자열을 분리(i18n 키)해 둔다.
- 데이터 규모: 작품 수십~수백 개.

## 3. 데이터 제약

- 한 성우가 한 작품에서 여러 캐릭터를 맡을 수 있다.
- 한 캐릭터를 여러 성우가 맡을 수 있다 (하차·교체, 아역/성인, 대역 등).
- 같은 언어라도 더빙판이 여러 개일 수 있다 (예: 투니버스판, 넷플릭스판).

## 4. 확정된 결정사항

| 항목 | 결정 |
|---|---|
| 작품 범위 | 애니(TV, 극장판, OVA, ONA)와 게임으로 시작. `type` 필드로 확장 가능하게 |
| 배역 구조 | 작품 → 버전(언어 + 더빙판) → 배역(캐릭터 × 성우) |
| 작품 단위 | 시즌·극장판·OVA는 각각 별개 작품. 상위 개념인 **프랜차이즈**로 묶음 |
| 캐릭터 단위 | 프랜차이즈 단위로 정의하고 작품 간 공유 |
| 배역 변경 | 담당 회차 범위, 배역 구분(교체/아역/회상 등), 사유를 선택 필드로 저장 |
| 성우 식별 | 불변 고유 ID. 원어/로마자/한국어 표기와 별칭 저장. 동명이인은 ID로 구분 |
| UI 언어 | 한국어 우선, 추후 다국어 |
| 즐겨찾기 | **프랜차이즈 단위** + 성우. `localStorage` + JSON 내보내기/가져오기 |
| 스포일러 | 캐릭터 스포일러는 이름 등을 "스포일러"로 가리고 성우는 표시. 배역 스포일러는 성우를 가림. 클릭하면 표시 |
| 다국어 데이터 | 표시용 데이터는 ja/ko/en 3개 언어 체계. 고유명사는 원어·로마자 필수, 다른 언어는 공식 표기만. 서술형은 3개 언어 필수(공식 번역이 없으면 직접 번역하고 표시) |
| 역할 구분 | 주연 / 조연 / 단역 (게스트는 단역에 포함). 단역과 이름 없는 배역까지 전부 수집 |
| 성우 겹침 표시 | 언어별 섹션으로 분리 (일본어 → 한국어 → 기타) |
| 검색 | 부분 일치 + 자동완성. 초성 검색은 후순위 |
| 출처 | 모든 레코드에 출처 URL 필수. 신뢰도 등급 운영 ([06](06-data-collection.md) 참고) |
| 검증 상태 | `unverified` / `verified` / `disputed` / `user_confirmed`. 미검증 데이터도 배지로 구분해 표시 |
| 수집 흐름 | 로컬 실행 → 검증 → 문제 부분 재실행 → 재검증 → 남은 문제는 사용자 확인 → 브랜치·PR 생성 → 머지 |
| 스킬 관리 | 수집·검증 스킬은 레포에 포함. 실행 전 최신 main을 받고, 실행 중인 스킬 내용 해시를 레포 최신본과 비교해 다르면 갱신 후 갱신된 스킬로 재실행 |
| 이미지 | 성우(선택)·캐릭터 이미지를 지원. 레포에 파일을 저장하지 않고, Tier 1~2 출처의 원본 URL을 저작자 표기와 함께 참조 |
| 빌드 | 런타임은 브라우저 전용. 배포 시 GitHub Actions 빌드 허용 |
| 프레임워크 | React + Vite + TypeScript ([02](02-architecture.md) 참고) |
| 브라우저용 DB | SQLite 대신 빌드 시 생성하는 사전 계산 인덱스 JSON ([04](04-data-build.md) 참고) |
